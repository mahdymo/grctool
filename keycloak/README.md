# Keycloak configuration (spec §5)

One realm per partner + one internal realm (spec §5.1). Realms are imported
at container start from `realms/` (`--import-realm`). MFA (TOTP) is enforced
via the `CONFIGURE_TOTP` default required action; WebAuthn can be enabled per
realm policy. Session/token lifetimes implement spec §5.3: access token 15
min, idle 30 min, absolute 8 h. Brute-force protection on (spec §6.2).

| Realm | Purpose |
|---|---|
| `ehsanlab-internal` | Our team: EhsanLab Admin / Consultant roles, control-plane OIDC client, customer1 SAML client |
| `partner-a` | Whitelabel demo partner: partner-admin + customer roles, per-customer groups with `instance` attribute |

## Role mapping (spec §5.2 → platform)

| Spec role | Realm role | Enforcement |
|---|---|---|
| EhsanLab Admin | `ehsanlab-admin` (internal realm) | control plane API + CISO Assistant superuser |
| EhsanLab Consultant | `ehsanlab-consultant` | control plane object-level checks (assigned customers) |
| Partner Admin | `partner-admin` | control plane (own-partner filter), realm admin of own realm only |
| Customer Admin | `customer-admin` + group `customers/<customer>` | CISO Assistant instance admin, group→instance attribute gates access |
| Control Owner | `control-owner` + group | CISO Assistant object-level permissions on assigned items |
| Auditor | `auditor` + group | read-only + report export (spec ambiguity resolved: read + export) |

## Wiring CISO Assistant to Keycloak (per instance)

CISO Assistant (django-allauth) federates via SAML. After the stack is up:

1. In Keycloak, note the realm's SAML IdP metadata URL:
   `http://auth.grc.localhost/realms/<realm>/protocol/saml/descriptor`
2. In CISO Assistant admin (`/admin/`), create a **Social Application**:
   provider = SAML, client = the instance's SAML client (e.g.
   `ciso-assistant-customer1`), IdP metadata URL as above.
3. Verify login redirects to Keycloak and a TOTP-enrolled user lands back
   authenticated. Local password login stays available only for the break-glass
   admin (spec §5.1).

Group→instance restriction: users must be members of `customers/<customer>`
whose `instance` attribute matches the instance they log into; the control
plane provisioning script sets the matching SAML client per instance, and
Keycloak's client scope mapping refuses tokens for foreign groups (fail
closed, spec §6.1.6).

## Identity brokering (Phase 2 prep)

Per-partner SSO (Entra ID / Google Workspace) is added as an
`identityProviders` entry in the partner realm — the protocol-level
requirement (spec §5.1) is met by Keycloak's brokering; no code changes.

## Dev secrets

Realm files carry no secrets. Dev client secrets are generated by Keycloak at
import; read them from the admin console (`http://auth.grc.localhost`,
bootstrap admin from `compose/.env`). Prod secrets come from the secrets
manager via the provisioning script — never committed (spec §6.1.2).
